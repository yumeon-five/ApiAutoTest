# API 接口测试用例 Markdown 模板

本文档只描述最终用例文件的 Markdown 结构。生成策略、覆盖范围、断言写法和索引回写规则见 `testcase-spec.md` 与 `skill.md`。

## 文件命名

`<接口名>_测试用例.md`

## 文件模板

```markdown

## < 接口名 > - < 场景名称 >

### 用例信息

| 字段 | 内容 |
| ---- | ---- |
| 用例编号 | <用例编号> |
| 测试标题 | < 接口名 >-< 场景名称 > |
| 前置条件 | < 前置条件 > |
| 优先级 | < 优先级 > |

### 请求信息

| 项目 | 内容 |
| ---- | ---- |
| 请求URL | < URL >< 请求路径 > |
| 请求方法 | < 请求方法 > |

### 请求头

| 参数名 | 值 | 说明 |
| :----- | :--- | :--- |
| < 请求头名称 > | < 请求头值 > | < 请求头说明 > |

### URL参数

| 参数名 | 值 | 说明 |
| :----- | :--- | :--- |
| < 参数名 > | < 测试数据占位符 > | < 参数说明 > |

### 请求体参数

| 参数名 | 值 | 说明 |
| :----- | :--- | :--- |
| < 参数名 > | < 测试数据占位符 > | < 参数说明 > |

### 预期结果

- 响应状态码：< HTTP状态码 >
- 响应格式：< 响应格式 >
- < 业务断言1 >
- < 业务断言2 >
```

## 填写规则

- 每个用例文件**只**包含 `frontmatter` 和 `## 详细用例` 两个部分。**禁止生成"用例总览"章节**。
- `关联接口 key` 写在 frontmatter 的 `interface_key` 字段，**不要**单独写表格或章节。
- 多条用例时，每条用例追加一个 `## < 接口名 > - < 测试标题 >` 详细段落。
- 无请求头、无请求参数、无请求头时保留表格标题，预留一个 空行，不要删除整节。
- 动态测试数据统一使用 Jinja2 风格占位符：`{{ 变量名 }}`，例如 `{{ 正确账号 }}`、`{{ 有效Token }}`。
